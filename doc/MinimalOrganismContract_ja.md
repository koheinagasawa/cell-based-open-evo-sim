# 最小個体実験の生命史と I/O 契約

**関連タスク:** `roadmap_ja.md` の P0-01、P0-02、P1-01〜P1-05、P2-01〜P2-03

**状態:** P0-01 の契約は確認・承認済み。ただし P0-02 の決定により、旧基質前提を撤回し、旧出力位置8を削除して18入力・8出力とする。
初回は推進を要求せず身体運動を調べる。P0-02 の初回実験の仕様は承認済みであり、実装・数値検証・Phase 2 の完了を意味しない。
現在は下記の「慣性あり物理コアと数値診断の実装結果」まで実装・検証した。
出生なしの World への物理接続と通信からの分離も、下記の P2-03 の範囲で確認した。
新しい出生スケジュールと CPPN 身体経路は未接続である。

## 契約の一覧

以下は本書の承認済み事項の要約である。理由・制約・後続の未決事項は各節を参照する。

| 項目 | 初回の契約 |
|---|---|
| 対象 | 種 Cell から成長する個体の2D 世界内での身体運動。初回は推進を要求せず、平面外の基質は仮定しない |
| 媒質抵抗 | 円形 Cell ごとに独立した線形粘性抵抗。身体全体や Cell の連なりの形・配置・向きによる抵抗補正は入れない |
| 運動 | Cell の慣性を残し、質量・速度と線形粘性抵抗で運動を扱う。半陰的 Euler 法と初期パラメータは下記の承認済み判断に従う |
| 接触 | 円の重なり量に比例する柔らかい反発力。変形の近似として有限の重なりを許容し、共有境界は計算しない。初回は接触摩擦なし |
| 物理結合 | 現在長と目標長の差に比例する線形ばね。基準目標長は両端 Cell の半径の和。両端に等しく逆向きに作用し、両端 Cell の収縮・伸長指令の単純平均から目標長を決める |
| 初期化・再発生 | world 原点の種 Cell 1個。発生座標・State・年齢・速度はゼロ、結合なし |
| 継承・所有 | Genome、Interpreter、Profile 決定規則を継承。Agent 内で Genome と Interpreter を共有し、可変 State は各 Cell が所有する |
| Profile | 全 Cell 共通。誕生時に決め、生涯固定 |
| 入力18要素 | 発生座標2、自分の State 4、物理結合先の現在相対位置8、存在マスク4 |
| 出力8要素 | 次 State 4、出芽ゲート1、配置オフセット2、収縮・伸長1。Raw Vector を Interpreter が解釈する |
| State | 新しい Cell はゼロから開始し、更新は二相。相手の State は参照しない |
| 出芽・結合 | ゲートが0.5を超えたときに要求し、条件を満たせば親子間に物理結合1本を作る。各 Cell 最大4結合、入力4枠 |
| 成長の制約 | 初期エネルギー63、出芽コスト1。控除後の残りを親子等分。総 Cell 数上限64。子への無償エネルギー付与なし |
| 発生・行動 | 最初から両方を許可し、同じ CPPN + Interpreter を使う。観察区間の境界で出芽停止や制御器切替はしない |
| 初回の対象外 | 明示的通信、State 交換、Field 入力、外部時刻入力、既存 Cell 同士の追加結合、自律生殖 |
| 実装時の確認 | 保存形式・既存 logger への接続などは「仕様確定の範囲と実装時の確認」を参照 |

## 対象と問い

**変更済みの旧判断（P0-01）:** 一つの種 Cell から結合した多細胞体へ成長し、
身体と環境の相互作用によって 2D 空間を移動する個体を最初の対象としていた。
**承認済み（P0-02、初回の観察範囲）:** まず独立した円形 Cell の線形粘性抵抗だけで、
発生した身体の変形・運動を調べ、Agent 全体の推進を成功条件にしない。
移動する個体という目標を取り消すのではなく、初回の機構確認と分けて後続で検討する。
完成形や動作周期は指定せず、発生・行動を同じ CPPN + Interpreter で扱う。

問いは「発生した身体が、その後の行動に関わる経路を作れるか」である。
目指す証拠はまず機構の成立であり、この契約だけで進化、選択応答、自律生殖、OEE を確立しない。
餌への誘導、捕食、自律生殖は初回の対象外とする。
初回の環境反作用は下記の媒質抵抗の方針に従い、推進のための物理機構は今回追加しない。
既存の位置を直接変更する `move` は、身体を介した移動の証拠に用いない。

## CPPN の自己座標

**承認済み（P0-01）:** 実空間の現在位置とは別に、Cell ごとに固定した
「発生座標」を CPPN の自己座標入力に使う。

| Cell / 時点 | 発生座標の決め方 |
|---|---|
| Agent 初期化時の種 Cell | 原点とする |
| 出芽で生まれる新しい Cell | 親の固定された発生座標に、出芽時の配置オフセットを足して決める |
| 誕生後 | 実空間で移動・変形しても変更しない |

ここで「誕生時」とは新しい Cell が生成される時点であり、既存の `bud` では出芽時に相当する。
これは同一 Agent 内の成長であり、子孫 Agent の生成とは区別する。
発生座標は祖先からの出芽オフセットを積み上げた文脈であって、
「誕生時の実位置から、最初の種 Cell の実位置を引いた座標」ではない。
現在の周囲の状態は、下記の「初回の入力配置」に定める物理結合近傍からの局所入力として別に扱う。

**理由:** 移動後の出芽に親の移動履歴を混ぜず、発生上の位置の手掛かりと現在の物理的な位置関係を分ける。
代案の world 現在座標や現在の個体重心からの相対座標は、移動・変形・成長で自己座標が変わるため、
今回は採用しない。発生座標だけで移動・回転不変性や再発生の頑健性が保証されるとは主張しない。
出芽オフセットは world の x・y 軸で表す。方向と距離への変換は下記の P0-02 の出芽配置の判断に従う。
その定義によって今回の固定座標の意図を保てなくなる場合は、この判断を再検討する。

## 既存実装との対応

- `simulation\agent.py`: Agent 内で Genome と Interpreter を共有して Cell を生成する基盤がある。
- `simulation\cell.py`: 現在の `sense()` は world 上の現在位置を入力する。上記の発生座標は未実装であり、
  導入時は既存実験の入力を黙って置き換えず、新実験の経路として区別する。Cell ごとの State と二相更新の基盤はある。
- `simulation\interpreter.py`: Raw Vector のスロット解釈と Profile 別の写像を扱う基盤がある。
- `simulation\policies.py`: 同一 Agent 内の出芽と、誕生時の Profile 選択を扱う基盤がある。
  現在の `BaseBudding` は親からコストを引き、子には別設定の `init_energy` を与える。
  下記の親からのエネルギー分配契約が実装済みとは扱わない。
- `simulation\physics\spring.py`: 現在のばねは通信にも使う `conn_out` の各辺から両端への力を計算する。
  物理結合近傍を、通信の送信先一覧とそのまま同一視しない。新しい物理結合の分離は下記の P2-03 の実装範囲に従う。

## Profile

**承認済み（P0-01）:** 初回は種 Cell と出芽した Cell のすべてに同じ固定 Profile を与える。
Profile は誕生時に決め、その Cell の生涯中は変更しない。
Profile の決定規則そのものの変異は、ロードマップどおり Phase 4 まで導入しない。

**理由:** 発生座標・局所入力・State による挙動差を使い、まず身体の発生と行動の経路に絞る。
複数の固定 Profile を誕生時に選ぶ案は、最初の機構確認には必須とせず今回は採用しない。
この構成では Profile による用途の使い分けや共存を検証できない。
文脈別の解釈を必要とする実験へ進む際に、複数 Profile の導入を再検討する。

## Cell State

**承認済み（P0-01）:** State は用途を固定しない4要素とする。
種 Cell と出芽した Cell はともにゼロで開始し、親 Cell の現在 State はコピーしない。
各ステップで Interpreter が Raw Vector から取り出した次 State を予約し、
全 Cell の更新計算後に同時に反映する二相更新を使う。
時間的な変化は Cell ごとの State の明示的フィードバックで表現する。

**理由:** 既存の4要素 State と二相更新を利用し、初期化と更新の方式を増やさない。
親の実行時 State を新しい Cell へ引き継ぐ案は今回は採用しない。
4要素は最小実験の選択であり、一般に十分な記憶容量であるとは主張しない。
次元や誕生時初期化の変更が必要になった場合は、I/O 契約の変更として別条件で扱う。

## 初期化・継承・観察区間

**承認済み（P0-01）:** 各 rollout は world 原点に置いた種 Cell 1個から開始する。
種 Cell の発生座標・State・年齢・速度はゼロとし、結合を持たない。
Genome、Interpreter、Profile の決定規則を継承し、
成体の身体・Cell の現在 State・結合をコピーせず、子孫の rollout も種 Cell から再発生させる。
Agent 内で共有する Genome と Interpreter、および Cell ごとの可変 State の所有は、
`roadmap_ja.md` の中核契約に従う。

最初のステップから出芽と物理 Action の両方を許可し、同じ CPPN + Interpreter を使い続ける。
初期の発生観察区間と、その後の行動評価区間を設けるが、
区間境界で出芽を止めたり、別の制御器へ切り替えたり、成熟判定を必須としたりしない。
出芽の許可は成功の保証ではなく、以下の成長条件を満たした要求だけを実行する。
観察区間の長さは下記の P0-02 の判断に従う。
行動評価中にも成長できるため、下記の「身体実験の記録粒度」に従い、
身体の移動と Cell 追加による重心変化を区別して記録する。

**理由:** 発生と行動を一つの生成・解釈経路で扱い、成体のコピーや外部の動作スクリプトに置き換えない。
外部 rollout の再初期化と予算の初期付与は実験側の足場であり、環境内での自律生殖ではない。

**承認済み（P0-02、観察期間）:** 初回の rollout は合計1,000制御区間、シミュレーション時間100とする。
区間開始から最初の200制御区間、時間0〜20を初期の発生観察窓とし、
続く800制御区間、時間20〜100を後半の運動観察窓とする。
通常設定では合計10,000物理ステップ、物理刻みを半分にした精度比較では20,000物理ステップとなる。
時間20の境界で出芽の停止、制御器の切り替え、成熟判定は行わない。
初期から運動でき、後半にも出芽できる。初期窓の終了までに身体が完成する保証はない。

**理由と停止の区別:** 固定した有界な予算で発生と身体運動を観察するための初期値であり、
静止した個体だけ早期終了させず、正常な rollout は同じ期間を観察する。
期間の終了は予定された正常終了とし、安全上の異常による途中停止とは区別して記録する。
この長さで必要な現象を十分観察できると保証せず、観察期間の見直しが必要になった場合は理由と条件変更を記録する。

### 成長の予算

**承認済み（P0-01）:** 初回は有限の初期エネルギーと正の出芽コストを設け、
さらに総 Cell 数・step 数の安全上限を置く。出芽はエネルギー・結合数・総 Cell 数の条件を満たす場合だけ成功する。
最大4結合という局所上限だけを、個体全体の増殖を止める仕組みとは扱わない。
成長による子 Cell の誕生時にはエネルギーを無償で新規付与せず、親からの分配で扱う。
初回のために摂食・Field・代謝系一式を導入することは前提にしない。

**理由と限界:** 成長に使える量の制約と、実験を有限にする安全策を分けて保証する。
予算不足でも出芽要求を出し続けることはあり得るため、
制約で出芽できなくなることを「適切な成長停止が進化した」と解釈しない。
初期量と出芽コスト・境界条件・総 Cell 数上限は下記の判断に従う。観察期間は上記の判断に従う。
エネルギーは今回の18要素入力には含めず、条件判定に用いる。入力への追加が必要なら契約変更として扱う。

**承認済み（P0-02、出芽時のエネルギー分配）:** 出芽成功時は親のエネルギーから出芽コストを引き、
残りを親子へ半分ずつ分配する。親子の合計エネルギーは出芽コストの分だけ減り、子への無償付与は行わない。
配置条件などで出芽が不成立になった場合は、コストの徴収も分配も行わない。
初期エネルギーと出芽コスト、エネルギー不足時の出芽成立条件は下記の判断に従う。

**理由と影響:** 分配比率を指定する出力を追加せず、親子へ同じ成長予算を渡すため。
親に多く残す方式は今回は採用しない。コスト控除後の親の予算も半分になるため、
この分配規則が成長の仕方に影響することを実験条件として明示する。

**承認済み（P0-02、エネルギーの用途）:** 初回のエネルギーは出芽予算だけに使う。
維持費と収縮・伸長の費用は設けず、エネルギー不足による死・Cell の除去も導入しない。
出芽予算が不足する場合はその要求を不成立とするが、CPPN・State の更新と身体運動は継続する。

**理由と限界:** 初回は成長と運動の経路に絞り、代謝や死の仕組みを先に追加しないため。
この値は成長予算であり、ばね・運動の物理エネルギーとは別である。
アクチュエータの仕事の供給元や消費は計上しない近似とし、自己維持や熱力学的な収支の成立とは扱わない。
維持費・身体 Action の費用は、それらを必要とする問いへ進む段階で再検討する。

**承認済み（P0-02、成長予算の具体値、規模の見直し後）:** 種 Cell の初期エネルギーは63、
出芽成功1回あたりのコストは1とする。親のエネルギーが1以上ならエネルギー条件を満たし、1未満なら出芽不成立とする。
ちょうど1で成功した場合はコスト控除後の親子のエネルギーがともに0となるが、身体運動は継続する。
追加供給がなく、出芽以外に増減しないため、個体全体の出芽成功回数は最大63回、種 Cell を含む総数は最大64となる。
予算を各 Cell に分配することや配置・結合数の条件により、実際にこの総数へ到達できる保証はない。
これは初期実験の成長予算であって、完成形や総数64への到達を成功条件にする判断ではない。
独立した安全策としても総 Cell 数上限を64とし、成立した子と予約中の子を含めて判定する。
上限を超える出芽要求は費用なしで不成立とする。実際に64を超える Cell が存在すれば実装上の不整合として失敗にする。

**置き換えた判断と理由:** 初期エネルギー15・予算上最大16 Cell の承認済み設定を置き換える。
16 Cell では身体の広がり・枝分かれ・複数箇所の協調運動の観察を制限しすぎる懸念があるため、
まず最大64 Cell を許す設定へ広げる。64で十分なことや実行性能は未確認であり、実験で確認する。
コスト1とコスト控除後の親子等分は変更しない。

### 出芽の物質収支の適用範囲

**承認済み（P0-02）:** 初回の出芽は、物質収支を省略した有界な成長操作とする。
親の質量1を維持したまま質量1の子を追加し、その質量の供給元や環境中の物質の減少は計算しない。
有限の初期エネルギー、正の出芽コスト、総 Cell 数・step 数の上限で成長を制限するが、
エネルギー費用を払うことを質量・運動量保存の保証とは扱わない。
エネルギーについては、承認済みの親からの分配と子への無償付与なしの契約を維持する。

**理由・代替案・限界:** 初回は身体の発生と運動に絞り、親の質量分割や環境からの物質取り込みを追加しない。
これらの代替案は質量1固定を含む成長契約の見直しが必要になるため、今回は採用しない。
出芽を含む系全体を質量・運動量保存の成立例とは主張せず、子の初速度を選ぶだけで解消したとも扱わない。
出芽による重心・運動量の変化を自力での推進と区別して記録する。
物理更新の保存則の検証は Cell の構成が変わらない区間と分け、
媒質抵抗など承認済みの外力の作用も含めて判定する。
物質収支や出芽を含む保存則を調べる段階で、この省略と固定質量の契約を再検討する。

## 局所入力の近傍

**承認済み（P0-01）:** 初回の最小構成は、空間的近傍の代わりに
物理的に直接結合した相手を近傍入力の対象とする。
これは CPPN の観測対象の選択であり、結合していない Cell との接触などを物理法則から除外する決定ではない。

**理由:** 近いだけの Cell と力を伝え合う結合先を区別し、身体と行動の関係を入力に反映する。
既存の空間的近傍を流用する35要素案は未承認の提案であり、今回の方針で置き換える。
物理結合は通信接続や相手 State の直接参照を自動的に許可するものではない。
空間的近傍は、非結合 Cell の感知を必要とする実験で再検討する。

**承認済み（P0-01）:** 固定長へのまとめ方は、結合先ごとの個別枠と
存在マスクを使う。結合先が入っている枠のマスクは1、空き枠は0とし、空き枠の情報はゼロ埋めする。
マスクは結合の伸びや力の大きさではなく、入力枠の有効性を表す。
結合ごとの方向や変形を区別するため、平均などへの集約方式は今回は採用しない。

**承認済み（P0-01）:** 初回は1 Cell あたりの最大物理結合数と固定入力枠数を一致させ、
全結合先を観測する。入力枠を超えた結合先を黙って切り捨てる部分観測は採用しない。
この上限は身体の局所的な結合数を制限する実験条件であり、身体全体の Cell 数上限とは別に扱う。
出芽時に親子間へ1本作る規則に合わせ、初回は最大4結合・入力4枠とする。
親との結合も数えるため、出芽で生まれた Cell はさらに最大3個の子と結合できる。
結合方向や角度を指定するものではなく、身体全体の Cell 数上限でもない。

**理由:** 身体と入力を対応づけやすくし、初回の機構確認に観測対象の選別や情報欠落という追加要因を持ち込まない。
固定数だけを観測する案は結合数を入力枠から切り離せるが、今回は採用しない。

## 身体 Action の方向

**変更済みの旧判断（P0-01）:** 基質上での収縮・伸長と Cell ごとの基質抵抗の制御を選んでいた。
一様な overdamped 更新の内部力だけでは、成長などがない条件で重心移動につながらないことから、
基質抵抗も制御対象にするという理由だった。
ただし、平面外の基質を仮定する点が、P0-02 で承認した2D 世界の前提と合わないため、
この基質前提と基質抵抗指令の採用を撤回する。

**承認済み（P0-02）:** 世界の物理的な前提は `ProjectGrandDesign.md` の「2D 世界の物理的な前提」に従う。
接触摩擦と媒質抵抗を混同せず、媒質抵抗の近似が許容されることを、
Cell が抵抗係数を直接制御する機構の承認とは扱わない。

**承認済み（P0-02、媒質抵抗の方針）:** 初回は速度に線形な粘性抵抗を使う。
推進のために速度の二乗に比例する抗力や径の可変機能を先に追加せず、
まず線形粘性の条件で生じる運動を調べる。
径の可変機能は将来の候補であり、今回の承認には含めない。
円形 Cell ごとに、媒質に対するその Cell の速度から独立に抵抗を決める。
身体全体や Cell の連なりの形・配置・向きによる抵抗補正と、Cell 間の流れの相互作用は初回に導入しない。
抵抗差を作るための材質的な要素も追加しない。
径・抵抗係数は下記の「Cell の共通物理パラメータ」に従う。慣性の扱いは次の判断に従う。

**承認済み（P0-02、慣性の扱い）:** 初回は Cell の慣性を残し、
質量・速度を持つ Cell に駆動・結合・接触による力と線形粘性抵抗が作用するモデルを使う。
力と抵抗が瞬時に釣り合う慣性なしモデルではなく、加速・減速や惰性による身体運動を扱えるようにする。
線形粘性の採用は慣性の省略を意味しない。
質量は下記の共通設定に従い、積分方式は下記の「物理更新の数値方式」に従う。
速度の初期化は下記の「物理的な初速度」に従う。時間刻みは下記の数値方式の判断に従う。
既存の `PhysicsSolver` は慣性なしの更新として維持する。
新しい `InertialPhysicsSolver` の実装範囲と診断結果は下記の実装結果に従う。

**理由と制約:** 身体形状から抵抗を決める近似則を先に追加することを避け、
独立した円形 Cell の単純な抵抗則の下で身体運動を調べることに絞る。
流体全体の計算や身体形状に基づく抵抗近似は、今回の推進を成立させるためには採用しない。
これらの省略で身体と媒質の相互作用を十分再現できるとは主張せず、
推進を調べる必要が生じた段階でモデルの適用範囲を再検討する。

**モデル選択上の制約:** 全 Cell に同じ固定の等方的な線形抵抗を独立に与える
慣性なしモデルでは、成長・外部接触なしで内部力が釣り合う限り、Cell 位置の単純平均は動かない。
各 Cell が同じ質量なら、これは重心が動かないことに相当する。
非往復的な身体変形が生じても、この制約だけでは推進可能にならない。
選択した慣性ありモデルでも、同じ質量・同じ固定の等方的な線形抵抗係数を持つ Cell 群が
静止状態から始まり、成長・外部接触なしで内部力が釣り合う条件では、重心は動かない。
慣性の導入自体を推進が可能になる根拠とはしない。
身体変形の成立と Agent 全体の移動は別に計測し、モデルで排除した運動を探索不足と解釈しない。

### Cell の共通物理パラメータ

**承認済み（P0-02）:** 初回は全 Cell で半径0.5、質量1、線形粘性抵抗係数1を共通・固定とする。
媒質抵抗力は、媒質に対する速度ベクトルに抵抗係数を掛け、逆向きに作用させる。
Cell 間の径・質量・抵抗係数の差や、これらを変更する Action は導入しない。
これは Cell の直径を長さ1、質量を1、質量を抵抗係数で割った減衰時間を時間1とする無次元の基準設定であり、
現実の単位・生物の大きさ・媒質への対応づけは行わない。

**理由と受入上の注意:** まず共通の物理パラメータで、身体のつながりと指令による運動を調べるため。
ほかの力がない条件では、連続時間のモデルで速度が時間1につき初期値の exp(-1)、約37％へ減衰する。
この減衰則を数値計算で近似できることは今後確認する。
この基準設定だけで粘性支配や数値安定性を保証せず、ばね剛性・接触反発・時間刻みとの関係を別途確認する。
時間刻みや、ばねの運動に対する減衰の強さまで確定する判断ではない。

**承認済み（P0-02、剛性の初期実験値）:** 結合ばねの剛性を10、接触反発の剛性を100とする。
共通の無次元設定で、同じ長さのずれに対する接触反発を結合ばねの10倍強くし、
接触による大きな重なりを抑えつつ、非貫通拘束にはしない。
これは数値検証前の初期実験値であり、時間刻みと受入条件を併せて検証する。

**この比率の影響:** 半径0.5の Cell 2個だけを結合し、目標長を最小の0.8にした静的な条件では、
ばねと接触反発が釣り合う距離は (10 × 0.8 + 100 × 1) / (10 + 100)、約0.982となる。
重なりは直径の約1.8％で、目標長の20％収縮が実際の20％収縮になるわけではない。
接触しない伸長側にはこの反発による制限はなく、収縮側と応答が異なる。
これは2個の静的な釣り合いの計算であり、多細胞体や過渡的な運動の許容重なり量を保証しない。

### 物理的な初速度

**承認済み（P0-02）:** rollout 開始時の種 Cell の速度はゼロとする。
出芽した子の速度は、誕生時点である制御区間末の親の速度と同じ値で初期化し、親の速度は変更しない。
子と親の速度は独立した可変値として保持し、誕生後の一方の変更が他方へ漏れないようにする。
子の内部 State は従来どおりゼロとし、物理速度の初期化と内部 State の継承を区別する。

**理由と限界:** 移動中の親に対して子を速度ゼロで生む案は、出芽だけで親子に相対速度を生じさせるため採用しない。
初回は誕生直後の親子の相対速度をゼロにし、射出速度を追加しない。
これは身体全体の角速度を含む運動を再現する初期化ではなく、親の局所的な速度を使う単純な規則である。
質量1の子の追加に伴って運動量・運動エネルギーも追加され得る。
本書の「出芽の物質収支の適用範囲」に従い、これを出芽時の介入として記録し、保存則が成立したとは扱わない。

### 物理更新の数値方式

**承認済み（P0-02、積分方式）:** 初回の慣性あり物理更新は半陰的 Euler 法とする。
各物理ステップで、全 Cell の更新前の位置・速度から、ばね・接触反発・線形粘性抵抗の力を求める。
各 Cell の新しい速度を「更新前の速度 + 合力 / 質量 × 時間刻み」で計算し、
新しい位置を「更新前の位置 + 新しい速度 × 時間刻み」で計算する。
ある Cell の更新後の位置・速度を、同じ物理ステップの他の Cell の力計算に使わない。
媒質抵抗も更新前の速度から計算し、抵抗だけを別の陰解法や厳密減衰で処理する方式は初回には追加しない。

**理由と検証条件:** ばねを含む慣性ありの運動を小さな実装で扱い、
位置を更新前の速度で進める単純な陽的 Euler 法ではなく、新しい速度で位置を進める方式を選ぶ。
連立方程式を解く完全な陰解法ではなく、安定性や精度を方式の採用だけで保証しない。
時間刻みと受入誤差は以下の各判断に従い、時間刻みを半分にした比較を含めて検証する。

**承認済み（P0-02、制御と物理の更新間隔）:** 初期設定ではシミュレーション時間0.1ごとに、
CPPN・State・Action を1回更新し、その制御区間を時間刻み0.01の物理更新10回で進める。
物理更新中は収縮・伸長指令を保持するが、ばね・接触反発・媒質抵抗の力は各物理ステップの状態から再計算する。
出芽要求は制御更新の1回に対して判定し、物理更新ごとに繰り返さない。
State の二相更新は維持する。出芽の参加時点は次の判断に従う。

**承認済み（P0-02、制御区間内の順序と誕生時点）:** 初回の身体実験は次の順序で更新する。

5. 区間末に子と親子の物理結合を追加する。新生 Cell は次の制御区間から CPPN・物理更新に参加する。

子の実位置は、区間末の親の位置に予約した出芽オフセットを足して決める。
固定の発生座標は親の発生座標に同じオフセットを足して決め、物理更新による親の移動は混ぜない。
要求時点の親の実位置で配置を固定する案は、誕生までの親の移動で親子の距離が変わるため採用しない。
新生 Cell が同じ区間にさらに出芽する連鎖を避け、既存の区間末追加の方式に合わせるための判断である。
子の初速度と複数要求の受付順序は上記の各判断に従う。

既存の `World.step()` には物理更新後に新生 Cell を追加する基盤があるが、
この予約と区間末の配置・物理結合の契約が実装済みという意味ではなく、既存実験の挙動も一括変更しない。

**承認済み（P0-02、区間途中の失敗）:** 物理更新中の数値失敗・安全上限超過・timeout 等で失敗した場合、

### Cell 同士の接触

**承認済み（P0-02）:** 初回は円形 Cell 同士の重なり量に比例する柔らかい反発力を使う。
中心間距離が半径の和より小さいとき、中心を結ぶ方向へ、両 Cell に等しく逆向きの反発力を加える。
接触していない Cell 間には、この反発力を加えない。
反発の剛性は上記の初期実験値に従う。有限の重なりを許容するが無制限にはせず、
時間刻みと精度の受入条件は上記の判断に従い、運動中の重なり安全上限は次の判断に従う。

**承認済み（P0-02、運動中の重なり安全上限）:** 各 Cell 対の重なりが半径の和の20％を超えたら、
診断情報を保存して rollout を失敗として停止する。現在の共通半径では中心間距離0.8が境界となる。
各物理ステップで確認し、力の評価前の状態と位置更新後の状態のどちらにも上限超過を許さない。
位置を強制補正して継続せず、出生時の5％の成立条件とは別に扱う。
これは深い重なりで計算を続けないための安全基準であり、20％以内の物理的な正確さや数値精度の保証ではない。
精度の受入条件は上限以内でも別途満たす必要がある。
中心の完全一致も上限超過の失敗として扱い、この実験では任意の方向への押し分けで継続しない。
既存の反発力の完全一致時の処理を、他の実験も含めて削除する判断ではない。

**承認済み（P0-02、接触摩擦）:** 初回は接触摩擦を入れない。
重なりに対する法線方向の反発力は働くが、接触による接線方向の摩擦力は加えない。

**摩擦省略の理由と再検討条件:** 初回は推進を要求しない身体運動の観察に絞り、
摩擦係数、静止・滑りの切り替え、接触点の滑りに関わる回転の扱いを先に追加しない。
これは摩擦のない接触という近似であり、実際の組織の摩擦を再現したとは扱わない。
接触面での滑り抵抗を必要とする問いに進む場合は再検討する。

**理由と限界:** 重なりを接触による変形の粗い代理として扱い、
変形しない円盤の非貫通拘束を初回の必須条件にはしない。
これは Cell の共有境界・面積・体積を扱うモデルではなく、ボロノイ状の組織構造や体積保存を保証しない。
柔らかい反発力が将来の組織表現に必須という判断でもない。
共有境界を持つ組織を扱う段階では、接触モデルの置換を含めて再検討する。

`simulation\physics\repulsion.py` の反発力を新しい慣性ありソルバーでも再利用する。
新経路では力の計算前に上記の安全条件を確認し、完全一致時の既存の押し分け処理へ進まない。

### 物理結合と局所的な収縮・伸長

**承認済み（P0-02、結合の力学）:** 初回の物理結合は、現在長と目標長の差に比例する力を出す
柔らかい線形ばねとする。目標長より長いときは両端を引き寄せ、短いときは押し離し、
中心を結ぶ方向に両端へ等しく逆向きの力を加える。
収縮・伸長指令は Cell の位置を直接変更せず、この目標長を変える。
接触の反発力とは別に、出芽で生成した親子の物理結合に作用する。

**承認済み（P0-02、基準目標長）:** 収縮・伸長していないときの基準目標長は、両端 Cell の半径の和とする。
これは円がちょうど接する距離であり、出芽時の中心間距離を結合固有の自然長として保存する案は採用しない。
Cell の大きさから基準を決め、出芽配置によって自然長も変わる要因を初回には追加しないため。
出芽配置を直径1に固定する上記の判断により、親子の初期距離は基準目標長に一致する。
基準より短い目標長を指令する場合は接触反発と競合し、実際の距離は両者の力に依存する。
指令した目標長まで必ず収縮するモデルではない。指令の範囲と許容重なり量の整合は数値予算で確認する。

**承認済み（P0-02、両端の指令の合わせ方）:** 各物理結合の収縮・伸長指令は、
両端 Cell の指令の単純平均で決める。親子のいずれかを優先せず、同じ指令同士はそのまま、
同じ大きさで逆向きの指令は相殺される。
Raw Vector から Cell の指令への変換と、平均した指令から目標長への変換は、以下の各判断に従う。

**承認済み（P0-02、Raw 出力から指令への変換）:** Interpreter は収縮・伸長に割り当てた
Raw 出力を -1〜+1 にクリップして Cell の指令とする。-1 は最大収縮、0 は中立、+1 は最大伸長を意味する。
範囲内の有限値は変更せず、-1 未満は -1、+1 を超える値は +1 とする。
NaN・無限大はクリップせずエラーとして扱う。
各 Cell で変換した後に両端の指令を単純平均する。Raw 出力を先に平均してからクリップする方式ではない。
範囲内の値と指令の対応を保ち、CPPN の activation に依存せず物理 Action の範囲を保証するため。
範囲内の値も変換する `tanh` 案は今回は採用しない。範囲外では指令が飽和し、Raw 出力の大きさの差は指令に反映されない。
この指令値は長さそのものではなく、実際の目標長への変換と範囲は次の各判断に従う。

**承認済み（P0-02、目標長の更新方法）:** 各更新で、両端の平均指令を基準目標長に対する
伸縮率として使い、目標長を直接決める。目標長は「基準目標長 × (1 + 最大伸縮率 × 平均指令)」とする。
平均指令が0なら基準目標長、同じ指令を出し続ければ同じ目標長になる。
最大伸縮率は次の判断に従う。
指令を目標長の変化速度として積算する方式は、過去の指令に依存する結合の可変状態を追加するため、
今回は採用しない。目標長の変更は実際の距離の即時変更ではなく、Cell はばねの力・慣性・抵抗に従って動く。

**承認済み（P0-02、最大伸縮率）:** 初回の最大伸縮率は0.2とし、
平均指令 -1、0、+1 に対する目標長を、それぞれ基準目標長の80％、100％、120％とする。
これは基準長から大きく外しすぎずに伸縮の作用を観察するための初期実験値であり、
生物学的な正解や数値検証済みの条件とは扱わない。
ばね剛性・接触反発・時間刻みを合わせた検証で妥当性を判断し、
受入条件を満たさない場合は原因を記録して条件を見直す。
この値は実際の距離や許容重なりの上限ではない。収縮側では接触反発と競合するため、

**理由と実装状況:** 結合長を厳密に保つ拘束方式ではなく、結合の伸縮による身体変形と
慣性を伴う運動を扱うため。剛性は上記の初期実験値に従い、実際の長さの安全上限は次の判断に従う。
`simulation\physics\spring.py` の通信接続を使う受動ばねは既存経路として維持する。
新しい `simulation\physics\inertial.py` では、独立した物理結合・能動目標長・慣性あり更新を扱う。
CPPN からの指令生成と出生を含む World への接続は未実装である。

**承認済み（P0-02、結合長の安全上限）:** 実際の結合長が基準目標長の2倍を超えたら、
診断情報を保存して rollout を失敗として停止する。現在の共通半径では長さ2が境界となる。
力の評価前と各物理ステップの位置更新後に確認し、結合を切る、または長さを強制補正して継続する方式にはしない。
これは目標長の最大1.2とは別の安全上限であり、慣性や他の力による一時的な伸びを許しつつ過大な伸びを検出する初期値である。
物理的な破断長や、この範囲の計算精度を保証する値とは扱わない。
縮み側の過大な変形は、承認済みの接触重なり20％超過の安全基準で検出する。

**承認済み（P0-02、結合の破断）:** 初回は物理結合の破断を導入しない。
出芽で作った結合は伸び縮みしても維持し、まず身体の発生と結合を通した運動の確認に絞る。
破断した身体の所属や分離後のライフサイクルを先に追加しないため。
これは無制限の変形を許容する判断ではない。伸び・重なり・速度等は本書の承認済み数値上限を適用し、

### 身体実験の対照条件

**承認済み（P0-02、drive-off）:** 身体発生を含む主条件の対照は、

**比較の意味と限界:** 能動的な駆動を加えることが、発生を含む経路全体の身体と運動に及ぼす影響を調べる。

同じ完成身体に対する純粋な駆動効果の比較とは区別する。

### 最初の身体観察の genotype の用意

**承認済み（P0-02、初期個体の扱い）:** 最初の身体観察では seed 0〜4について、
共通の構造・初期化規則からランダムな CPPN を各1個生成する。

**承認済み（P0-02、初期 CPPN の構造と分布）:** 18入力、隠れ8ノード、8出力の
feedforward 固定構造とし、入力から隠れ層、隠れ層から出力層をそれぞれ全結合する。
入力から出力への直結や層内接続、構造変異、recurrence は追加しない。
隠れノードは `tanh` 4個、`sin` 2個、`gaussian` 2個、出力は全て `identity` とする。
各接続の重みは -1〜+1 の一様乱数を接続先の入力数の平方根で割った値とし、
全計算ノードの bias は -0.5〜+0.5 の一様乱数とする。
genotype 初期化専用の PCG64 を使い、seed ごとに独立に生成する。物理更新ではこの RNG を消費しない。
生成時のノード・接続の順序と RNG の初期化情報を再現可能な形で実装・保存する。

**理由と制約:** 小さな共通構造で、異なる activation による滑らかな変化・周期的変化・局所的反応の材料を用意する。
隠れノードに出力用途を割り当てず、身体や動作手順を埋め込まない。
重みの入力数による調整は加算値の過大化を抑えるための初期設定であり、最適な分布とは主張しない。
Raw 出力の用途・物理的制限は Interpreter 側の既存契約に従い、時間変化は Cell State の入力フィードバックで扱う。
出力層が `identity` であることを、用途ラベルや別の制御ネットワークの導入とは扱わない。

**経路の検証との区別:** 配線、出芽、State 更新等の接続の正しさは、
期待値の明確な小さな CPPN を使う別の決定論的なテストで確認する。
テスト用ネットワークによる身体や動作を、生物の成果として報告しない。
ランダムな5個では多細胞化・持続的運動を保証せず、現れなくても、
この初期条件で観察されなかったことと、機構の不成立・進化での獲得不可能を区別する。
ランダム観察だけで種 Cell からの発生・行動の機構成立や Phase 2 のゲート通過を保証しない。
身体経路を含む外部選択は Phase 3 の別実験として扱う。

## 出生なしの World への接続と通信からの分離（P2-03）

## CPPN 評価器の実装範囲（P1-01）

**設計判断（承認済み、P1-01）:** 当時の18入力・9出力は実験条件であり、評価器の固定定数にはしない。
初回の身体実験は上記の P0-02 の判断で18入力・8出力へ変更したが、以下の既存の接続確認は9出力のまま維持する。
「固定 I/O」は一つの実験・遺伝子型で宣言を固定する意味とする。
初期実装の18入力・9出力への固定を置き換え、入出力数を構築時の必須パラメータとして受け取る。
これにより実験条件を評価器から分離し、バックエンド切替やプラグイン機構などの汎用化は追加しない。

`simulation\cppn.py` の `CPPNGenome` は、呼び出し側が宣言した入出力数の feedforward CPPN を直接評価する。
正の整数の `input_size` と `output_size` を遺伝子型に保持し、構築後に切り替えない。
実験側は期待するサイズをこれらの引数として渡し、評価器は入力の長さと出力ノード数を宣言に対して検証する。
最小個体実験の接続確認では18と9を明示的に渡す。I/O 宣言も P1-02 の保存・復元対象に含める。
`NodeGene` に計算ノードの ID・activation・bias、`ConnectionGene` に接続元・接続先・weight を記述する。
入力ノードの ID は0から `input_size` 未満、計算ノードは `input_size` 以上とし、
`output_ids` に並べた `output_size` 個の計算ノードが Raw Vector の出力順となる。
ノード・接続・出力指定は不変な値として保持し、構築時に導出する評価順も同じネットワークの実行表現である。
別の制御ネットワークの重みを生成する仕組みではない。

実装は既存の NumPy と標準ライブラリだけを使い、
activation として `identity`、`tanh`、`sin`、`gaussian`（`exp(-x*x)`）を提供する。
単一の初期隠れ層構成は既定にせず、呼び出し側が有限の非巡回グラフを明示する。
これは指定された構造の評価機能であり、構造変異・交配・NEAT を導入したものではない。

ノード ID に基づく決定論的な評価順と、接続元 ID 順の加算で、宣言列の並べ替えによる計算順の変化を防ぐ。
評価中の値は呼び出しごとのローカル変数で、Cell の可変 State は入力として渡す。
`activate(inputs, rng=None)` は既存の Cell の呼び出しに合わせて RNG を受け取れるが、乱数を消費しない。
同じ環境の同じ genotype と入力で再現できることを対象とし、異なるプラットフォーム間のビット一致は保証しない。

不正な ID・重複・循環・未知 activation・非有限のパラメータ・入力不一致は `ValueError` で拒否する。
有限のパラメータと入力でも計算が発散した場合は `FloatingPointError` とし、
activation の飽和や成功形の既定出力で隠さない。
宣言された長さの Raw Vector を返すが、Action の意味や物理的な値域への変換はこの評価器に持たせない。

`tests\test_cppn.py` は数値計算、宣言順に依存しない評価、不正入力、RNG 非消費、
呼び出し間の実行値の分離、既存 `Cell.act()` と `ProfiledInterpreter` のベクトル解釈経路への接続を確認する。
異なる入出力数のネットワークを同時に扱えることと、ノード ID 境界・サイズ不一致の検証が宣言に従うことも確認する。
その接続確認では18要素入力を明示的に与え、`Cell.sense()` や World の物理・出芽経路は変更していない。
身体からの新入力生成とロコモーションは Phase 2 に残る。
保存・復元と独立コピー、固定構造の変異の契約は後続の各節に定める。

## CPPN genotype の保存・復元と独立コピー（P1-02）

**設計判断（承認済み、P1-02）:** `CPPNGenome` に `to_dict()`、
`from_dict(data)`、`copy()` を設ける。ファイル入出力は専用 API に含めず、
呼び出し側が標準ライブラリの `json.dump()` / `json.load()` で扱う。
遺伝子型と保存先・上書き方針を分離するためであり、専用のファイル保存・読込 API は今回は採用しない。
実験 artifact の管理に具体的な必要が生じた場合は、実験側の責務として再検討する。

保存形式の `schema_version` は整数の1とし、次のフィールドだけを持つ。

| フィールド | 内容 |
|---|---|
| `schema_version` | 保存形式のバージョン。genotype や実験の ID ではない |
| `input_size`、`output_size` | genotype が宣言する正の整数の入出力数 |
| `nodes` | `id`、`activation`、`bias` を持つ辞書の配列。出力へつながらないノードも含む |
| `connections` | `source`、`target`、`weight` を持つ辞書の配列 |
| `output_ids` | Raw Vector の順に並べた出力ノード ID の配列 |

`to_dict()` は毎回、新しい辞書とリストを返す。
ノードは ID 順、接続は `(source, target)` 順で出力し、`output_ids` の順序は変更しない。
数値は既存の構築時の正規化を通した Python の整数・有限の浮動小数とし、標準 JSON で保存できる。
評価順序や接続索引は派生値として保存せず、復元時に既存のコンストラクタで再構築する。
Cell State、身体、RNG、Interpreter、Profile 決定規則、系統情報はこの保存形式に含めない。
これは CPPN genotype 単体の形式であり、Agent の全継承情報や rollout checkpoint ではない。

`from_dict()` は最上位と各レコードの欠落・未知フィールド、未対応または型違いのバージョン、
配列・辞書の型違いを `ValueError` で拒否する。
その後、既存の genotype 検証で不正 ID、重複、循環、未知 activation、非有限値、I/O 宣言との不一致を拒否する。
補完、自動修復、将来バージョンの推測による読込は行わない。
実験が期待する I/O サイズとの一致は、保存形式そのものの制約にはしない。
ファイル I/O と JSON 構文エラーは標準ライブラリから呼び出し側へ伝播させる。

`copy()` はノード・接続と派生評価表を再構築した別の不変な `CPPNGenome` を返す。
親を書き換える可変 genotype は導入せず、子のパラメータ変更は新しい genotype の構築として扱う。
書き出した辞書やリストを変更しても、親や復元済みの子へ変更が漏れない。
コピーや復元に乱数は使わず、同じ環境の同じ入力で復元前後の出力が一致することを対象とする。
異なるプラットフォーム間のビット一致や、変異・選択への応答はこの項目では確立しない。

`tests\test_cppn.py` に標準 JSON ファイルでの round-trip、全 activation と非連続なノード ID、
出力順、出力へつながらないノードの保存、宣言順の正規化、不正形式・graph の拒否、
辞書・復元済み genotype・コピーの独立性のテストを追加した。

## CPPN の固定構造の変異（P1-03）

**設計判断（承認済み、P1-03）:** weight・bias に加えて activation も変異対象にする。
最初は数値パラメータだけに絞る案も検討したが、activation の変更は構造変異や NEAT なしで扱えるため、
今回から含め、不都合が観察された時点で除外を検討する。
3種類の変異は個別に無効化できる。activation を無効化した比較は別条件として記録し、
観察後に条件を変えた結果を当初条件の結果として扱わない。
Interpreter、Profile 決定規則、ノード・接続の追加削除、I/O 宣言と出力順は変更しない。

`CPPNGenome.mutate(config, rng)` は、独立した不変な子 genotype と、
実際の変更を列挙する不変な `MutationRecord` の tuple を返す。
World や Cell の生殖処理には接続せず、親のパラメータと実行結果を変更しない。

不変な `MutationConfig` には次の5値をすべて明示し、実験用の既定値は設けない。

| 設定 | 意味・制約 |
|---|---|
| `weight_probability` | 各接続の weight の変異確率。有限値、0以上1以下 |
| `bias_probability` | 各計算ノードの bias の変異確率。同上 |
| `activation_probability` | 各計算ノードの activation の変異確率。同上 |
| `weight_std` | weight に加える平均0の正規分布ノイズの標準偏差。有限値、0以上 |
| `bias_std` | bias に加える平均0の正規分布ノイズの標準偏差。同上 |

weight・bias は各パラメータを独立に確率判定し、選ばれた値にノイズを加える。
activation は `identity`、`tanh`、`sin`、`gaussian` のうち現在と異なる3種類から等確率で選ぶ。
出力ノードと出力へつながらないノードも計算ノードとして同じ規則で扱う。
activation の変更で出力が必ず変わるとは限らず、数値の小さな摂動でも挙動への影響が小さい保証はない。
確率と標準偏差の実験値、診断関数、評価予算は次節の P0-02 の遺伝診断条件に定める。

RNG は呼び出し側が明示的な `numpy.random.Generator` として渡し、変異処理内で生成しない。
計算ノードを ID 順に訪問し、各ノードの bias、activation の順で処理した後、
接続を `(source, target)` 順に訪問して weight を処理する。
確率0の項目と標準偏差0の数値変異は乱数を消費しない。
有効な項目は確率1でも確率判定の乱数を引き、選ばれた場合だけノイズまたは選択用の整数を引く。
activation の候補は名前の辞書順で並べてから選ぶ。
同じ環境・同じ親・同じ設定・同じ RNG 初期状態で、子、変更列、変異後の RNG 状態が再現されることを対象とする。
同じ RNG インスタンスを続けて使う呼び出しは、初期状態を戻した比較ではない。

変更記録は処理順に並べ、`parameter`、`gene_id`、`before`、`after` を持つ。
`gene_id` は bias・activation ならノード ID、weight なら `(source, target)` とする。
数値の比較で変更がない場合は記録せず、ノイズが丸めで消えた場合も空の変更として扱う。
すべて無効の場合も独立した子を返すが、変更列は空で RNG を消費しない。
seed、親子 ID、世代、設定と記録をまとめた保存は、次節の P1-04 の外部世代ループで扱う。
子 genotype は P1-02 の保存形式でそのまま復元でき、形式バージョンの変更は不要である。

不正な設定や RNG は `ValueError` で拒否する。
数値変異で非有限値が生じた場合は `FloatingPointError` とし、clip、再抽選、親を返す代替処理で隠さない。
失敗時も親は不変だが、それまでに消費した RNG は巻き戻さない。

`tests\test_cppn_mutation.py` は乱数の処理順、同一条件の再現、各変異の単独有効化、
activation の他3種類への切替、構造・I/O の保存、変更記録と親子の独立性、
変異後の JSON 復元、無効時の RNG 非消費、丸めによる無変更、不正入力・非有限値の拒否を確認する。
これらは変異操作の正しさのテストであり、選択応答、形態進化、activation 変異の有用性を実証したものではない。

## 非シミュレーション遺伝診断（P0-02 の遺伝条件、P1-04/P1-05）

**設計判断（承認済み）:** 「2入力の積の近似」を使い、
固定構造の CPPN の複製・変異・外部選択をつないだとき、同じ予算のランダム親選択より誤差が下がるかを調べる。
身体や行動の良し悪しを採点せず、遺伝経路と外部選択への応答だけを切り分けるための課題である。
この遺伝診断の設計では身体実験の I/O は変更しない。身体実験側の最新の I/O は上記の「初回の出力配置」に従う。
CPPN 自体を単体で直接評価し、Cell、World、Interpreter、Profile、可変 State はこの診断には持ち込まない。
この条件の承認によって P0-02 の身体実験条件まで完了したとは扱わない。

### 課題・初期化・継承

| 項目 | 承認済み条件 |
|---|---|
| 入力・目標 | 各入力値 `-1, -0.5, 0, 0.5, 1` の25組。第1入力を外側、第2入力を内側の順で列挙し、2値の積を目標とする |
| 評価 | 25点すべての平均二乗誤差。小さいほど良い。評価に乱数は使わず、条件間で省略やキャッシュによる評価予算の差を設けない |
| 固定 graph | 入力 ID 0・1、隠れノード ID 2〜5、出力 ID 6。入力→隠れ→出力の全12接続で固定 |
| 初期 activation | 隠れ4ノードは `tanh`、出力は `identity`。その後は出力を含め、既存の4種類の間で変異を許可する |
| 初期パラメータ | 各 bias・weight をそれぞれ `-1以上1未満` の一様分布で生成。ノード ID 順に5個の bias、続いて接続の `(source, target)` 順に12個の weight を引く |
| 継承 | 親 genotype から独立した子を構築する。構造と I/O は固定し、評価途中の値や前回出力は継承しない |
| 数値変異 | weight・bias の変異確率はそれぞれ0.2、加算ノイズの標準偏差はそれぞれ0.1 |
| activation 変異 | 各計算ノードの変異確率は0.05。現在と異なる既存3種類から等確率で選ぶ |

数値設定は診断の最初の条件であり、最適値や安定性を保証する値とはしない。
activation も最初から含める方針を維持する。除外や確率・強度の調整が必要になった場合は、
元の結果を残した別条件として記録し、好ましい結果が出るまで当初条件を黙って変更しない。

### 世代交代・対照・予算

各世代16個体、親候補の上位数は4とする。次世代16個体をすべて新しく作り、
成績の良い個体を無条件で残す elitism や、過去最良個体の再投入は行わない。
成績が同じ場合は、前世代の slot の数値順で順位を決める。

| 条件名 | 親選択 | 変異 | 比較目的 |
|---|---|---|---|
| `selection` | 前世代の誤差上位4個体から等確率で選ぶ | 承認済み設定を使用 | 主条件 |
| `random_selection` | 前世代の全16個体から等確率で選ぶ | 主条件と同じ | 選択の寄与 |
| `no_mutation` | 主条件と同じ | 3種類の変異確率をすべて0にする | 継承の安定性と初期個体の選別だけによる変化 |

mutation-off でも初期集団に差があれば選択による変化は起こり得るため、
「選択が不可能」の対照としては扱わない。
同じ root seed の3条件は同じ初期 genotype 集団を独立に作り、後続の親選択だけを条件に応じて変える。

root seed は `0, 1, 2, 3, 4` に固定する。
初期世代0に加えて25回の世代交代、すなわち世代0〜25を評価する。
1条件・1seed あたり416個体評価、10,400入力評価とする。
3条件・5seed の1組は6,240個体評価、156,000入力評価であり、
同じ設定をもう1回実行して再現確認する場合も同じ予算を使う。
本実行と再実行の合計は12,480個体評価、312,000入力評価となる。
P1-04 の小規模テストはこの診断の本実行として数えない。

RNG は `PCG64` を使い、`SeedSequence([root_seed, generation, slot, purpose])` から
候補ごと・用途ごとに独立した Generator を作る。purpose は初期化0、親選択1、変異2とする。
初期化は世代0だけで使い、3条件で root seed と導出規則を共有するが、Generator の可変状態は共有しない。
ID は各試行内で `g{generation}:i{slot}` とし、試行の root seed・条件と併せて識別する。

### 記録・失敗・判定

各条件・seed の出力先は分け、既存の出力ディレクトリには上書きしない。
genotype と親子関係は全候補を保存し、世代間で上書きしない。

| artifact | 内容 |
|---|---|
| `config.json` | 形式・実験定義の版、実効設定、入力・目標、RNG 導出規則、予定評価数。`no_mutation` の実効変異確率も明示する |
| `provenance.json` | コードの git revision・作業ツリー状態・関連差分、実行に使うソース本文とその UTF-8 テキストの SHA-256、Python・NumPy・platform・起動引数 |
| `candidates.jsonl` | 完了した候補の ID、親 ID、世代・slot、用途別 seed、genotype、変異前後の記録、誤差。各行を書き出した後に flush する |
| `metrics.csv` / `metrics.npz` | 完了世代ごとの累積個体評価数、最小誤差、誤差中央値。既存 `write_metrics_csv_npz()` を使う |
| `status.json` | `running` / `completed` / `failed` / `timeout`、記録済み評価数、保存済みの最終世代、処理中候補、失敗分類・理由、実時間 |

`completed_input_evaluations` は、記録済みの完了候補に対応する入力評価数である。
失敗した候補の途中計算を完了扱いにせず、その候補は status に残す。
候補の記録や途中の世代を、完全な試行として読み込まない。

1条件・1seed の実時間上限は60秒とし、メタデータ収集を含む運用上の中断として扱う。
候補評価とファイル操作の境界で協調的に確認し、git コマンドにも残り時間を渡す。
進行中のファイル I/O や1候補内の計算を強制終了する仕組みではなく、実行速度を適応度へ混ぜない。
timeout が起きた試行は比較用の完了結果に含めない。
不正入力、数値発散、provenance 取得失敗、artifact 保存失敗は、理由を記録して例外を呼び出し側へ伝播する。
低得点、親の差し戻し、再抽選で隠さない。出力先自体に書けない場合は記録も保証できないため、
伝播した I/O エラーを失敗として扱う。強制終了後に `running` のまま残る出力も未完了である。
途中再開や full checkpoint は今回の対象外とする。

P1-05 では全seedの最終集団の誤差中央値を主指標とし、
主条件とランダム親選択の seed ごとの差、初期からの変化を並べる。
改善率や統計的有意性を事前の成功保証にはせず、改善しなかった結果も保存する。
同じ環境で再実行した genotype・系統・誤差を比較し、変異なし条件では初期集団にない genotype が出現していないことを確認する。
誤差推移の画像化と3条件・5seed の比較・解釈は P1-05 で行う。
選択応答が観察できなければ、基盤のテスト成功だけを理由に Phase 1 の完了ゲートを満たしたとは扱わない。
この診断は形態進化、activation 変異の優位性、自律生殖、OEE を確立しない。

### P1-04 の実装範囲

`experiments\cppn_diagnostic\runner.py` の `run_diagnostic(config, out_dir)` は1条件・1seed を実行する。
World/Cell を前提とする既存 `runner_generic` に診断用の架空の身体を通すのではなく、
CPPN の評価・保存・変異と、既存のメトリクス writer を再利用した専用の小さなループとする。
汎用 evaluator registry、進化 DSL、NEAT、並列化、World の法則変更は追加しない。
`DiagnosticConfig` で個体数・世代交代数・親候補数・timeout・変異設定を指定でき、
CLI は seed と条件を必須指定にして、暗黙に全条件の診断を開始しない。
承認済み設定以外で実行した場合は別の設定として保存し、本予算の結果に混ぜない。

CLI の入口は `python -m experiments.cppn_diagnostic.runner`。
`--out-dir`、`--seed`、`--condition` は必須で、`--population-size`、
`--generations`、`--selected-parents`、`--timeout-seconds` を指定できる。
`tests\test_cppn_diagnostic.py` は小規模な条件で、評価値、固定予算、乱数・変異の再現、
親選択と同点処理、初期集団の共通化、系統の再構築、保存物の整合性、上書き拒否、
失敗・timeout の明示、CLI が指定した1試行だけを動かすことを確認する。
P1-04 の実装と小規模テストの後に、承認済み予算で P1-05 を実行した。結果は次節に記録する。

### P1-05 の実行・比較と観察

**状態:** 承認済みの3条件・5seed をそれぞれ独立に2回実行し、比較と画像保存を完了した。
条件・予算の調整、追加の seed 探索、失敗した試行の差し替えは行っていない。

`experiments\cppn_diagnostic\compare.py` を追加した。
`--execute` を明示したときだけ、既存 runner で承認済みの30試行を逐次実行する。
比較では完了状態・設定・評価数・provenance・CSV/NPZ と候補記録の整合性を確認し、
全 genotype の復元、seed からの初期化・親選択・変異の再構築、親子 ID の対応を検証する。
再実行との比較は、候補順と ID を保った全候補記録の一致で行い、時刻・実時間は比較に含めない。
保存済みの誤差を集計し直すが、追加の適応度評価は実行しない。
全変異を無効化した子が初期集団の genotype から逸脱せず、同一 genotype の誤差が変わらないことも確認する。
欠落、不一致、未完了は比較失敗として記録し、試行を除外して成功を報告しない。
同じ core ソースと実行環境が必要だが、core を変更していない後続 commit での再集計は許可する。

実行したコマンドは次のとおり。既存の出力先は拒否するため、再実行時は新しい `--run-root` を使う。

```powershell
$env:MPLBACKEND = 'Agg'
python -m experiments.cppn_diagnostic.compare --run-root outputs\cppn_product_p1_05_01 --execute
```

`17a2c24cc6232b9e67f56ddf5d7dbc39937157ca01f13a987dd78b631811d6d5` を `suite.json` に保存した。
core のソース本文・差分と環境、起動引数も各 provenance に保存している。

保存先は `outputs\cppn_product_p1_05_01`。

activation を無効化した対照は実行しておらず、その単独の寄与は分からない。
未評価の入力点への汎化、身体の発生・移動、形態進化、内生的選択、自律生殖、OEE は検証していない。
