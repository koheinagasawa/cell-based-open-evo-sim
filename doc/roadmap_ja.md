# ロードマップ

**基準日:** 2026-09-06

**状態:** 設計再整理後。以下の Phase 0 以降は未完了。

## 目的と読み方

本プロジェクトの目的は、人間が完成形や動作手順を設計せず、発生・身体・環境・継承の相互作用から、
多様な形態と意味のある動きを持つ「ありえたかもしれない生き物」を生み出すことである。
Open-Ended Evolution（OEE）は長期的な方向性だが、有限の実験で得られる形態・行動・系統の変化も重要な成果とする。

この文書は `ProjectGrandDesign.md` を実装と実験へ接続する着手順である。
近い Phase は小さな変更単位まで具体化し、遠い Phase は手前の実験結果で変わり得るため意図的に粗く記す。
Phase 番号は旧ロードマップを置き換える。既存基盤があっても、新しい各 Phase の完了を意味しない。

人間は世界法則、利用可能な操作、遺伝表現、実験条件を設計する。
一方、最終的な身体や動作スクリプトを成功条件として手で与えない。
課した環境課題、計算上の上限、介入は、生物側の成果と分けて記録する。

## 全体マイルストーン

| Phase | 観察できる到達点 | まだ確立しないこと |
|---|---|---|
| 0 | 最小個体実験の契約と比較条件が一つに定まる | 実装、進化、物理方式の一般解 |
| 1 | 同じ CPPN 遺伝子型を復元・変異・外部選択できる | 形態進化、NEAT の構造進化、OEE |
| 2 | 一つの種 Cell から発生した身体が、環境との物理的相互作用を通じて行動する | 進化の成果、自律生殖 |
| 3 | 遺伝的な身体・行動差が、再発生後も結果と選択応答に影響する | 自発的な生殖、生態系、OEE |
| 4 | Genome・Profile・Interpreter の自由度を一つずつ増やし、用途の追加を系統上で比較できる | 累積進化や外適応の保証 |
| 5 | 共有環境内で Agent の誕生・成長・生殖・死が循環する | 多様性の維持、無期限の進化 |
| 長期 | 多様な生き方、環境改変、物質系、3D を根拠に基づき拡張する | 無限の組合せだけによる OEE の保証 |

Phase 1 の遺伝基盤と Phase 2 の身体基盤は、Phase 0 の契約後に並行して進められる。
両者は Phase 3 で初めて一つの遺伝・発生・行動・選択サイクルになる。
完全な NEAT、内生的生殖、化学系は Phase 3 の前提ではない。

## 現在の基盤と不足

### 利用できる基盤

| 領域 | 現在あるもの |
|---|---|
| Cell 更新 | State の二相更新、Profile、出力スロット、接続とメッセージ受信 |
| 解釈 | `ProfiledInterpreter` による Profile ごとのベクトル割り当て |
| Genome 例 | `experiments\chemotaxis_bud\genomes.py` などの手書き実装 |
| 成長 | `AgentBudding` による同一 Agent 内の Cell 追加 |
| Field | 減衰する Gaussian source の和としてのサンプリング |
| 通信 | 接続を介したメッセージ配送と次フレーム受信 |
| 物理 | soft repulsion、受動ばね、overdamped な位置更新 |
| 実験 | `ExperimentSpec`、`runner_generic`、メトリクス、イベント・フレーム保存 |

Field は現時点では完全な拡散系でも、消費可能な資源循環でもない。
`AgentBudding` は個体の成長であり、子孫 Agent を作る生殖ではない。
標準の `move` による位置の直接変更は接続確認用の足場であり、身体を介した移動の証拠ではない。
soft repulsion とばねがあることを、hard collision constraint の完成とは扱わない。
また、`runner_generic` は現在 Cell 中心の生成経路を持つため、Agent 単位の rollout は必要に応じて適応する。

### 中核的な不足

- 進化可能な CPPN 遺伝子型と、同じネットワークを Cell ごとに実行する経路。
- 遺伝子型の複製・変異・系統記録と、決定論的な外部世代ループ。
- 身体の配置や結合によって結果が変わる局所アクチュエータと環境反作用。
- 子孫を種 Cell から初期化し直し、発生と行動を再現するライフサイクル。
- 生物学的な子孫 Agent の生成と、再生可能で消費可能な資源を含む生態系。

## Genome 実行・継承契約

Genome は CPPN 自体であり、各 Cell の更新時に直接評価する。
NEAT は後に、その同じネットワークのグラフとパラメータを進化させる。
CPPN が別の固定制御 NN の接続重みを生成する HyperNEAT 型を、本ロードマップの前提にはしない。

```text
Agent が共有する CPPN Genome
  + Cell の位置・身体/物理接続・近傍・環境・自身の State
  -> 用途ラベルを持たない Raw Vector
  -> Interpreter（Cell の固定 Profile で写像を選択）
  -> 次 State + 発生/通信/物理 Action
  -> World が身体・環境を更新
  -> 変化した局所条件が次ステップの入力へ戻る
```

遺伝子型の記述と実行用にコンパイルしたオブジェクトは分けてもよいが、別の制御ネットワークにはしない。
ネットワークのパラメータは Agent 内で共有し、可変 State は Cell ごとに持つ。
将来 recurrence を導入する場合も、その実行時状態の所有者を Cell ごとに明示する。

継承するのは Genome、Interpreter、Profile の生成・選択規則である。
成体の身体、Cell の現在 State、生成済み Profile をそのまま複製せず、子孫は原則として種 Cell から再発生させる。
Profile は Cell 誕生時に生成または選択し、その Cell の生涯中は固定する。
時間変化は、feedforward CPPN の段階でも Cell State の明示的フィードバックで表現できる。

外部世代ループでは、実験側が結果を記録・比較して親を選び、遺伝子型を複製・変異する。
この段階では、生物自身が行う生殖 Action を実験側の複製・継承処理で代行する。
遺伝と再発生は検証するが、生殖行動の進化や環境内での自律的な世代継続を検証したとは扱わない。
World の法則と明示的評価を混同せず、後の内生的選択は別実験で評価する。

## Phase 0: 最小個体実験を定義する

**目的:** 「最初に観察したい、発生して行動する最小の個体」を一つだけ定義する。 **依存:** なし。最初に着手する Phase。

| ID | 状態 | タスク | 完了条件 |
|---|---|---|---|
| P0-01 | [ ] | 最小実験の生命史と I/O 契約を短く定義する | 種 Cell、CPPN 入力、Raw Vector、Interpreter 出力、Profile 決定、State 更新、発生期間と行動期間が一枚で追える |
| P0-02 | [ ] | 物理・予算・比較条件を決める | 身体が役立つ場面、局所 Action、環境反作用、観察時間、資源・Cell・step 上限、seed 集合、記録値、baseline が列挙される |

P0-01 では、座標入力が world 絶対座標、個体座標、発生時座標、現在位置のどれかを明示する。
身体 topology、物理的な Cell 接続、メッセージ接続、CPPN graph topology は別概念として名前を分ける。
子孫はどの初期 State と配置に reset され、何を遺伝するかもここで固定する。
発生と行動は時間的に重なってもよい。
観察期間や評価開始条件は定めるが、成熟後の別制御器や必須のフェーズ切替は設けない。

P0-02 では、物理ソルバー名を先に一般化しない。
遺伝診断の予算・seed・比較条件と、身体実験の物理条件は分けて決定し、後者の未決を理由に前者を待たせない。
Phase 1 の非シミュレーション診断には物理方式の確定は不要だが、形態実験の前には
接触、摩擦または他の環境反作用、速度の扱い、結合拘束、`dt`、反復回数と許容誤差を選ぶ。
PBD/XPBD は候補であり、慣性や特定方式が全ての進化に必須とはみなさない。

未解決の実験パラメータは、この Phase の設計判断として残し、根拠なく実装値を確定しない。
ただし長い抽象仕様を作ること自体を門番にせず、二つの文書タスクが満たされたら実装へ進む。

**対象外:** 複数環境、汎用実験 DSL、完全な物理エンジン、成功する最終形態の指定。

## Phase 1: 小さな直接実行 CPPN と遺伝経路

**目的:** 形態より先に、実際の CPPN 遺伝子型を決定論的に評価・複製・変異・選択できることを確かめる。 **依存:** P0-01。P1-04/P1-05 の実験前に P0-02 の遺伝診断用予算・比較条件を決める。物理方式の確定は不要。

| ID | 状態 | タスク | 完了条件 |
|---|---|---|---|
| P1-01 | [ ] | 固定 I/O の小さな CPPN 評価器を追加する | 同じ genotype、入力、seed から同じ Raw Vector が得られ、core 経路が辞書出力で Interpreter を迂回しない |
| P1-02 | [ ] | genotype の保存・復元と独立コピーを実装する | topology、weight、bias、node activation を round-trip でき、子の変更が親へ漏れない |
| P1-03 | [ ] | 明示的 RNG を使う固定構造の変異を実装する | 同じ親・mutation config・seed で同じ差分になり、変更内容を列挙できる |
| P1-04 | [ ] | 有界な外部 population loop を実装する | 親 ID、子 ID、変異、seed、結果を記録し、世代数・個体数・timeout を設定できる |
| P1-05 | [ ] | 事前宣言した小さな非シミュレーション診断を行う | 復元、継承、個体間分離、変異応答を測り、no-selection と no-mutation の対照を目的別に比較できる |

最初は CPPN の graph を固定し、重みなどの小さな変異だけでよい。
診断関数の詳細は P0-01 後に選ぶが、形態や OEE の代理と主張しない。
no-selection または random-selection は選択の効果を調べる対照である。
mutation-off は継承の安定性を調べられるが、「選択が不可能」の証明には使わない。

Phase 1〜3 では Interpreter と Profile の生成・選択規則を固定し、まず CPPN の変異の影響を調べる。
固定は全 Cell を同一 Profile にする意味ではなく、文脈に応じた既定の選択も含む。
これらの規則自体の変異は Phase 4 で追加する。

既存の `ExperimentSpec`、runner、logger を再利用しつつ、進化フレームワークを先に一般化しない。
不正な genotype、未知 activation、I/O 不一致、hook failure は記録して失敗させ、成功形の既定値へ黙って置換しない。

**完了ゲート:** 決定論、serialize/restore、親子の独立性、系統記録をテストし、
事前宣言した toy 診断で変異と外部選択への測定可能な応答を再現できる。

**対象外:** NEAT の構造変異、交配、speciation、身体発生、生命らしさの主張。

## Phase 2: 身体に意味がある最小物理と発生

**目的:** 同じ Genome + Interpreter が種 Cell から身体を作り、その身体を介して環境内で行動する経路を作る。 **依存:** P0-01、P0-02。Phase 1 の完了や完全な NEAT は不要。

| ID | 状態 | タスク | 完了条件 |
|---|---|---|---|
| P2-01 | [ ] | 局所的な身体 Action と環境反作用を一つ定義する | Cell が位置を直接書き換えず、Action、身体結合、接触・摩擦等を通して結果が生じる |
| P2-02 | [ ] | 最小ソルバー構成と数値予算を実装する | 選んだ接触・結合・速度処理が有限値を保ち、`dt`・反復・許容誤差の受入条件を満たす |
| P2-03 | [ ] | 物理結合と方向付き message link の意味を分離する | 通信接続の有無が意図せず質量・剛性・破断特性を決めない。共有する場合は意味を明記する |
| P2-04 | [ ] | 種 Cell から決定論的に成長する経路を作る | CPPN が Cell ごとに直接実行され、bud、誕生時 Profile、接続、上限が再現される |
| P2-05 | [ ] | 発生と行動を同じ Genome + Interpreter で接続する | 別の発生 NN や固定完成身体なしに、発生後も同じ共有 network が Cell State と局所入力から Action を出す |
| P2-06 | [ ] | 身体依存性の対照実験を保存する | 同じ drive でも topology 差で測定結果が変わり、drive-off/no-movement 対照と有限値・step 上限を確認できる |

内部力だけで重心移動しない条件では、移動しないことを solver bug と決めつけない。
環境との接触、摩擦、流体抵抗、基質への作用など、選んだ世界法則の下で身体が役立つ関係を作る。
維持費、Action cost、簡単な scalar resource は導入してよいが、化学系を前提にしない。

手書きパラメータは機構確認に使えるが、それによる身体を「進化した生き物」と報告しない。
Cell 数、位置、速度、拘束誤差、作用量、step 時間に上限を設け、発散や上限到達を保存する。

**完了ゲート:** 種 Cell からの発生と身体を介した行動が再現でき、
身体 topology または配置の差が同じ局所 drive に対する測定結果を変える。

**対象外:** 高機能な剛体・流体エンジン、一般 3D、進化成果、自律生殖。

## Phase 3: 遺伝・再発生・行動・選択を一巡させる

**目的:** Phase 1 と Phase 2 を結び、遺伝的な身体・行動差が再発生後の結果に影響するかを調べる。 **依存:** Phase 1、Phase 2。ここが最初の中核実験。

| ID | 状態 | タスク | 完了条件 |
|---|---|---|---|
| P3-01 | [ ] | Agent-aware な単一 candidate rollout を作る | 固定 seed/初期 State から一 Agent を成長・行動させ、Cell 群を Agent 単位で集計できる |
| P3-02 | [ ] | 外部 evaluator と遺伝的世代交代を接続する | 結果記録、親選択、genotype copy/mutation、reset、種 Cell からの再発生が明示的に分離される |
| P3-03 | [ ] | 再現可能な run artifact を定義する | config/version、全 RNG seed、世代、lineage、mutation、失敗理由、checkpoint が保存される |
| P3-04 | [ ] | 身体・行動・環境結果を対応づけて保存する | 初期/最終状態、間引いた trajectory、形態、物理 topology、Profile、行動、resource/cost を親子で比較できる |
| P3-05 | [ ] | 有界な main experiment と baseline を実行する | population、generation、step、seed、Cell、timeout の上限内で複数 seed と固定条件を再実行できる |

評価は World の法則ではなく実験側に置き、何を選択圧として与えたかを明記する。
成功形態や動作を直接採点せず、環境内の結果と単純な予算を使う。
失敗、絶滅、発散、timeout、上限悪用を黙って低得点または成功へ丸めない。
full mid-world snapshot は必要性が出るまで任意とし、再実行に必要な遺伝・設定・RNG 情報を先に保証する。

事前に固定した複数 seed で、random/no-selection と、同一遺伝子を変異させず再発生させる対照を比較する。
固定 mapping と可変 mapping の比較は Phase 4 で行う。
任意の改善率や統計的有意性を先に約束せず、観察予算と比較方法を P0-02 で固定する。
課した cap を明示し、harness の隙を利用した結果を生命現象として数えない。

**完了ゲート:** 親子の genotype 差が、種 Cell からの反復発生後にも身体または行動差として現れ、
その差が環境結果に影響する。外部選択条件の応答を baseline と比較できる。

これは遺伝と再発生の実験であり、自発的生殖、自己維持する生態系、OEE の達成ではない。
「別位置でも全特徴が再生する」など、実際に比較していない頑健性は主張しない。

## Phase 4: 進化自由度と文脈依存の用途を増やす

**目的:** 一度に全てを可変にせず、Genome graph、Profile 選択、Interpreter mapping の寄与を分離して調べる。 **依存:** Phase 3 の再現可能な中核実験。

| ID | 状態 | タスク | 完了条件 |
|---|---|---|---|
| P4-01 | [ ] | NEAT の実装・統合方針を決める | 利用ライブラリか最小自作範囲、innovation、継承、互換性、I/O 保護の責務が明確になる |
| P4-02 | [ ] | CPPN graph の小さな構造変異を導入する | node/link 変更後も必須 I/O が有効で、保存・復元・mutation log が再現できる |
| P4-03 | [ ] | 必要最小限の互換性・speciation 実験を行う | 小集団で構造差の扱いを観察でき、導入しない対照と同じ予算で比較できる |
| P4-04 | [ ] | 離散 Profile の誕生時選択を進化対象にする | 成熟 Cell の Profile 書換えではなく、発生時の生成・選択規則として遺伝・記録される |
| P4-05 | [ ] | Interpreter の slot assignment を変異可能にする | mapping 差を lineage 上で追跡し、固定 mapping 条件と同じ予算で比較できる |
| P4-06 | [ ] | 制御された共進化実験を行う | Genome、Profile、Interpreter の可変項目を段階的に組み合わせ、単独条件との差を保存する |
| P4-07 | [ ] | 用途の再解釈・共存・継承を区別して調べる | mapping 介入や機能無効化により、新用途と既存用途の寄与を子孫まで追える |

NEAT の一式は Phase 3 の前提ではなく、Phase 4 でも必要な範囲から導入する。
アルゴリズム上の crossover と、生物が行う交配 Action は別問題である。
最初から mating や大規模な speciation を必須にせず、構造変異の実験が要求した時点で追加する。

再解釈、既存用途との共存、発生・行動・継承を通じた累積進化は別々の達成である。
異なる action label へ割り当てた数だけで Exaptation を定義しない。
lineage と介入により、既存能力を利用した新しい用途か、単なる破壊・置換・再配線かを調べる。

小さな変異でも壊れる、あるいは大きな変異だけが残る結果は重要な観察であり、
安定化機構を自動追加して隠さない。連続 Profile や任意 mapping は、離散実験が必要性を示した後に検討する。

**完了ゲート:** 同一予算の固定条件と可変条件を比較し、どの自由度が何を変えたかを lineage 上で説明できる。
用途追加が観察された場合も、累積進化の一般的保証とは表現しない。

## Phase 5: 共有環境での自律 Agent ライフサイクル

**目的:** 外部 rank-based selection を外し、共有環境内の誕生・成長・生殖・死による選択へ移る。 **依存:** Phase 3。Phase 4 の全項目完了は必須ではない。

| ID | 状態 | タスク | 完了条件 |
|---|---|---|---|
| P5-01 | [ ] | 成長と子孫 Agent 生成を別 Action/イベントとして定義する | 個体内 bud と、genotype を継承した種 Cell の birth を識別できる |
| P5-02 | [ ] | 単純で有限・再生可能な resource と cost balance を導入する | 初期付与だけでなく摂取、維持、Action、生殖、更新の収支が追跡できる |
| P5-03 | [ ] | Agent membership と death cleanup を一貫させる | Cell 死亡、Agent 消滅、子孫分離が物理・ログ・集計に反映される |
| P5-04 | [ ] | 身体境界と子孫の物理的分離規則を決める | ownership、bond、message、接触の扱いが birth 前後で曖昧にならない |
| P5-05 | [ ] | 外部順位選択なしの有限生態実験を行う | birth/death、resource、density、lineage を記録し、初期エネルギー消費後も再生産を評価できる |

最初は無性生殖でよい。交配や生物学的 crossover は、それ自体が研究対象になった時点で追加する。
有限資源、密度、競争条件を明記し、個体数の一時的増加だけで再生産成功と判定しない。
実際の birth/death event と、初期に与えた資源を超える世代継続を記録する。

絶滅、一形態の固定、静的な占有も結果として報告する。
身体の有用性と、異なる身体が共存する条件は別問題であり、多様性を保証しない。
novelty、niching、diversity intervention を使う場合は別条件として表示し、implicit fitness の結果に混ぜない。

**完了ゲート:** 共有環境内で Agent の birth/death と資源収支を直接数え、
外部 evaluator が親を選ばなくても複数世代の lineage を再実行・検証できる。

**対象外:** 完全な化学、無制限の生態系、OEE の断定。

## 長期ブランチ

以下は Phase 3〜5 の bottleneck が実測され、追加することで検証可能な機会が増える場合に進める。
順序と採否は実験結果から決め、カレンダー期限を置かない。

- **持続する形態・行動多様性:** niche、環境変動、相互作用、環境改変を別条件として比較する。
- **3D 化:** 2D では存在しない身体配置、接触、移動、生態的機会を試す明確な問いができた時に導入する。
- **物質循環:** Atom、Matter、Inventory、Composition、排泄、死骸、材料置換を小さく段階導入する。
- **環境改変:** 堆積、土壌、局所資源変化、stigmergy が lineage と生存結果へ与える影響を測る。
- **化学空間:** 既存法則から生じる結合を必要時に計算・登録する遅延評価と、
  外部イベントが新法則・資源を注入する仕組みを区別する。

組合せ空間が大きいこと、未知物質を登録できること、質量収支を持つことだけでは、
エネルギー整合性、機能の積み上げ、OEE を保証しない。
open-endedness は長期の lineage、表現型、相互作用、環境変化から別途測定する。

## 横断方針

### 決定論と系統

- genetic evaluation、World、Agent、Cell の RNG 所有者と seed 導出を明示する。
- genotype ID、parent ID、generation、mutation、experiment config/version を一緒に保存する。
- 位置由来 spawn key を単純な生成順 counter へ置き換えることを既定にしない。順序不変性を損なう可能性がある。
- 同一位置で同じ乱数列になる問題と UUID tie-break の影響は、まず再現テストを作ってから方式を決める。
- 再現比較の打切りは原則として step 数や評価回数で定める。実時間 timeout は運用上の中断として記録し、機械速度依存の打切りを遺伝子の適応度や決定論的な選択結果へ黙って混入させない。
- 不正入力、数値発散、hook 失敗、artifact 欠落を成功扱いせず、失敗理由を保存する。

### 検証の分離

- 新しいロジックには決定論的な単体テストを追加し、一つの論理変更を一つの commit にする。
- 物理の数値正しさ、発生の再現性、遺伝の再現性、進化上の主張を別々の gate にする。
- 既存経路を壊さず、必要なら experiment option で新経路を選択する。
- hand-coded 個体の機構確認と、進化で獲得した結果を明確に区別する。
- 人間が設計した環境課題・action・cap と、生物が獲得した身体・行動を別項目で報告する。

### 性能と観察

- 実際の実験を profile し、Cell 数、step 数、field source 数、接続辺数、frame 保存頻度と時間・メモリを記録する。
- ばね処理は全 Cell pair ではなく接続辺を走査するため、基本的な計算量を `O(N + E)` として測る。
- Field の source accumulation、近傍探索、frame/metric 出力の費用も含めて bottleneck を特定する。
- 予算超過が観測される前に spatial grid、backend migration、並列化を必須化しない。
- 最適化の trigger と保持すべき決定論・数値誤差を、対象実験ごとに決める。
- frame、画像、trajectory をファイル保存できれば当面十分とし、GUI を前提にしない。

## 直近の実施順

次に行うのは **P0-01** だけである。
一つの最小個体について、種 Cell、局所入力、Raw Vector、Profile、State、Action、
発生・行動の観察範囲、子孫へ渡すものと reset するものを短く定義する。

P0-01 のレビュー後、まず **P1-01〜P1-03** へ進める。
P0-02 の遺伝診断用予算・比較条件が揃えば **P1-04/P1-05** へ進み、身体実験用の物理条件が揃えば **P2-01〜P2-06** へ進む。
各項目を独立した小変更として進め、Phase 1 と Phase 2 の両 gate 後に Phase 3 へ合流する。
Phase 4、Phase 5、長期ブランチは、この中核実験から得た失敗と bottleneck が着手根拠になるまで開始しない。
